### 44 — Чаты без владельца
- **Домен:** Чаты
- **ICP:** руководитель поддержки / админ портала
- **Боль:** непонятно, кто отвечает за чат, сообщения «висят»
- **Эффект:** меньше чатов без ответственного
- **MVP:** список чатов без владельца, назначение владельца, дайджест руководителю
- **Риск:** не везде есть сущность владельца — нужна настройка
- **Скоринг:** A4 / B4 / C4
- **Источник:** `PROPOSED.md`

### 45 — Контроль повторных касаний по сделке
- **Домен:** CRM
- **ICP:** РОП, тимлид продаж
- **Боль:** менеджер «дёргает» клиента слишком часто или слишком редко
- **Эффект:** ровнее ритм follow‑up, меньше потерянных сделок
- **MVP:** правила «мин/макс дней между активностями», список нарушений, алерт
- **Риск:** разные воронки требуют разных ритмов
- **Скоринг:** A4 / B4 / C4
- **Источник:** `PROPOSED.md`

### 46 — Задачи без оценки / чеклиста перед стартом
- **Домен:** Задачи
- **ICP:** тимлид, руководитель проекта
- **Боль:** задачи стартуют без понятного Definition of Ready
- **Эффект:** меньше возвратов и переносов сроков
- **MVP:** чек‑лист готовности задачи, список нарушений, напоминание постановщику
- **Риск:** сопротивление команды — мягкий режим отчёта
- **Скоринг:** A3 / B4 / C4
- **Источник:** `PROPOSED.md`

### 47 — Сравнение менеджеров: активность vs результат
- **Домен:** Аналитика
- **ICP:** РОП, коммерческий директор
- **Боль:** много звонков/дел, но мало выигранных сделок — или наоборот
- **Эффект:** быстрее находят неэффективные паттерны работы
- **MVP:** панель «активности / выигранные / сумма» по менеджерам, сравнение периодов
- **Риск:** не сводить к «палочной» системе — показывать контекст
- **Скоринг:** A5 / B4 / C4
- **Источник:** `PROPOSED.md`

### 48 — Эскалация тишины в групповых чатах проекта
- **Домен:** Чаты / Задачи
- **ICP:** руководитель проекта, тимлид
- **Боль:** по проектному чату давно нет ответов на открытые вопросы
- **Эффект:** меньше зависших решений в переписке
- **MVP:** ручная метка «ждёт ответа», очередь тишины, эскалация через N часов
- **Риск:** права IM; без чтения текста сообщений
- **Скоринг:** A4 / B3 / C3
- **Источник:** `PROPOSED.md`

### 49 — Напоминания по выбранным сообщениям
- **Домен:** Чаты
- **ICP:** любой сотрудник
- **Боль:** важное сообщение теряется в ленте
- **Эффект:** меньше забытых договорённостей
- **MVP:** «напомнить позже» из сообщения, личный список напоминаний
- **Риск:** дублирование штатных напоминаний
- **Скоринг:** A4 / B4 / C5
- **Источник:** `PROPOSED.md`

### 55 — Задачи с просроченным согласованием
- **Домен:** Задачи
- **ICP:** тимлид, руководитель проекта
- **Боль:** задача ждёт принятия/согласования и зависает у постановщика или наблюдателя
- **Эффект:** меньше простоев на этапе приёмки
- **MVP:** очередь задач «на проверке» дольше N часов, дайджест постановщику
- **Риск:** разные статусы приёмки в командах
- **Скоринг:** A4 / B4 / C4
- **Источник:** `PROPOSED.md`

### 56 — Дайджест «что изменилось за день» по CRM
- **Домен:** Аналитика / CRM
- **ICP:** РОП, коммерческий директор
- **Боль:** сложно быстро понять, что произошло в воронке за день
- **Эффект:** меньше времени на ручной обзор перед планёркой
- **MVP:** ежедневный дайджест: новые лиды, выигранные/проигранные, просрочки, крупные смены стадий
- **Риск:** шум — нужен жёсткий топ‑N и фильтры
- **Скоринг:** A5 / B4 / C4
- **Источник:** `PROPOSED.md`

### 58 — Контроль сделок с истёкшей «датой следующего контакта»
- **Домен:** CRM
- **ICP:** РОП, тимлид продаж
- **Боль:** дата следующего контакта прошла, а активности нет
- **Эффект:** меньше «молчащих» сделок с формально проставленной датой
- **MVP:** список просроченных next-contact дат, алерт, быстрое создание дела
- **Риск:** поле даты может быть пользовательским — нужна настройка
- **Скоринг:** A4 / B4 / C4
- **Источник:** `PROPOSED.md`

### 64 — Контроль повторного открытия закрытых сделок
- **Домен:** CRM
- **ICP:** РОП, владелец CRM
- **Боль:** закрытые сделки снова открывают без причины и ломают отчёты
- **Эффект:** меньше хаоса в статусах и чище аналитика
- **MVP:** журнал повторных открытий, список за период, дайджест РОПу
- **Дополнение:** автоматизация простановки причины/метки при повторном открытии (обязательный выбор из справочника)
- **Риск:** легитимные переоткрытия — нужна метка причины
- **Скоринг:** A3 / B4 / C4
- **Источник:** `PROPOSED.md`

### 65 — Задачи без связи с проектом/группой
- **Домен:** Задачи
- **ICP:** руководитель проекта, тимлид
- **Боль:** задачи создают «в воздухе» — их сложно контролировать
- **Эффект:** выше доля задач в правильных проектах
- **MVP:** список задач без группы/проекта, правила обязательности, напоминание постановщику
- **Дополнение:** автоматизация простановки проекта/группы (по умолчанию из родительской задачи / последнего проекта постановщика / правила отдела)
- **Риск:** личные задачи нужно исключать настройкой
- **Скоринг:** A4 / B5 / C5
- **Источник:** `PROPOSED.md`

### 66 — Радар аномалий активности менеджеров
- **Домен:** Аналитика
- **ICP:** РОП, тимлид продаж
- **Боль:** резкое падение звонков/дел замечают слишком поздно
- **Эффект:** раньше видят просадку дисциплины
- **MVP:** сравнение активности с прошлой неделей, пороги Δ%, алерт/дайджест
- **Риск:** шум в праздники — рабочие дни и исключения
- **Скоринг:** A4 / B4 / C4
- **Источник:** `PROPOSED.md`

### 80 — Подзадачи без дедлайна при дедлайне родителя
- **Домен:** Задачи
- **ICP:** руководитель проекта, тимлид
- **Боль:** у родительской задачи срок есть, у подзадач — нет
- **Эффект:** меньше сюрпризов ближе к дедлайну проекта
- **MVP:** список нарушений, напоминание постановщику, отчёт по проектам
- **Риск:** не всем подзадачам нужен свой срок — исключения
- **Скоринг:** A4 / B5 / C5
- **Источник:** `PROPOSED.md`

### 87 — Журнал передачи чата между операторами
- **Домен:** Чаты
- **ICP:** руководитель поддержки, тимлид операторов
- **Боль:** чат передали, новый оператор не взял его в работу
- **Эффект:** меньше потерянных передач
- **MVP:** журнал handoff, SLA первого действия после передачи, дайджест
- **Статус проработки:** докрутить концепцию (механику handoff, права IM, антишум)
- **Риск:** права IM; без чтения текста
- **Скоринг:** A4 / B3 / C3
- **Источник:** `PROPOSED.md`

### 91 — Сравнение среднего чека по менеджерам и источникам
- **Домен:** Аналитика
- **ICP:** РОП, маркетолог
- **Боль:** смотрят только количество сделок, не средний чек
- **Эффект:** лучше видят, кто/какой канал приносит дороже
- **MVP:** средний чек выигранных сделок, фильтры, сравнение периодов
- **Риск:** выбросы крупных сделок — медиана опционально
- **Скоринг:** A4 / B5 / C5
- **Источник:** `PROPOSED.md`

### 92 — Контроль ответов на @упоминания руководителей

- **Боль:** руководителя упомянули, ответа нет, решения тормозятся
- **Эффект:** меньше «висящих» эскалаций в чатах
- **MVP:** очередь неотвеченных упоминаний выбранных ролей, порог N минут, дайджест
- **Риск:** права IM; антишум и исключения
- **Скоринг:** A4 / B3 / C3
- **Источник:** `PROPOSED.md`

### 95 — Задачи без результата в комментарии при закрытии
- **Домен:** Задачи
- **ICP:** тимлид, руководитель проекта
- **Боль:** задачу закрывают без краткого итога — сложно аудировать
- **Эффект:** прозрачнее история выполнения
- **MVP:** правило комментария при завершении, список нарушений, отчёт по проектам
- **Риск:** сопротивление — мягкий режим и исключения по типам задач
- **Скоринг:** A3 / B4 / C4

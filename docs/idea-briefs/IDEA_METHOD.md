# Метод генерации идей: от API Bitrix24

Цель — не плодить однотипные «пустые поля → список → алерт», а искать идеи от **возможностей платформы**.

## Конвейер (каждый час)

1. Прочитать `PROPOSED.md`, `BACKLOG.md`, пул идей — исключить повторы.
2. Выбрать **1–2 API‑угла** из ротации ниже (не повторять углы последних 5 часов; вести блок `## Ротация углов` в конце `PROPOSED.md`).
3. Для каждого угла спросить: какую **измеримую пользу** дать за 1–2 недели на стандартных объектах CRM / Tasks / IM / Analytics.
4. Сгенерировать **ровно 5 идей** разных механик; микс доменов ≥ 3 из 4.
5. Записать в `PROPOSED.md` со сквозной нумерацией и обновить «Следующий свободный номер».
6. Закоммитить и запушить в `master` (без PR), если пользователь это уже разрешил для потока идей.

## Формат идеи (обязательно)

- **API‑угол** — какой примитив/методы
- **Placement** — где живёт в Bitrix24 (карточка, список, меню, чат, дашборд приложения)
- **Механика** — событие / история / связь / агрегат / UI‑действие
- Домен, ICP, боль, эффект, MVP, риски, скоринг A/B/C
- Строка `в беклог N`

## Ротация API‑углов

| Код | Угол | Примеры API / точек | Какие идеи искать |
|-----|------|---------------------|-------------------|
| A | События | `event.bind`, ONCRM*, OnTask* | триггеры, автодействия, журналы в момент изменения |
| B | История стадий/статусов | `crm.stagehistory`, task history | скорость, проскоки, переносы, handoff |
| C | Связи сущностей | deal↔contact↔company↔activity↔task | разрывы цепочек, орфаны, контекстные панели |
| D | Агрегаты и периоды | `*.list` + фильтры дат | аномалии Δ%, план/факт, радары без «пустых полей» |
| E | Оргструктура и права | user, department, access | дежурства, очереди, эскалации по роли |
| F | UI placements | CRM_*/TASK_*/IM_* placements | killer‑кнопка в контексте объекта |
| G | IM‑метаданные | dialog/chat timestamps, participants | SLA/очереди **без текста сообщений** |
| H | Чеклисты и время | checklist, elapseditem | DoR, приёмка, план/факт часов |
| I | Дубли и поиск | crm.duplicate, phone/email match | дедуп, повторные лиды (не просто «пустое поле») |
| J | Товарные строки | product rows на сделке | чек, структура продаж, аномалии состава |

## Анти‑шаблоны (не генерировать)

Идея **запрещена**, если она сводится только к:
- пустое поле X → список → уведомление;
- «нет следующего дела»;
- «ещё один дайджест просрочек».

Такой паттерн допустим **только** если ядро — событие, placement‑действие, история или автопроставка данных.

## Красные флаги skill

- Нет внешних интеграций и отраслевых решений
- Нет тяжёлого realtime/стриминга и сложных чат‑ботов в MVP
- Time‑to‑value ≤ 10 минут
- Минимальные права; для чатов — без хранения текста сообщений

# Идея 317 — Из чата сделки создать дело себе

## 1) Коротко
Кнопка в чате сделки CRM: за 1 клик создать **дело на себя** с датой и привязкой к этой сделке — чтобы договорённость «перезвоню завтра» не умерла в ленте.

## 2) ICP
- Менеджер продаж (ответственный по сделке)
- Аккаунт той же компании

Не для РОПа‑дашборда и не для подрядчиков.

## 3) Боль и JTBD
Когда в чате сделки с коллегой договорились о следующем шаге с клиентом, чат закрывают — дело не создают. Follow‑up срывается, сделка остывает.

**Job:** когда в чате сделки зафиксировали следующий шаг, хочу сразу поставить дело себе на сделку, чтобы не потерять касание.

## 4) Эффект
Меньше слитых follow‑up после внутренних договорённостей в чате сделки.

## 5) УТП
**«Из чата сделки — дело себе на сделку за один клик.»**

## 6) MVP
1. Кнопка/пункт в чате, привязанном к сделке.
2. Мастер: тип дела (звонок/дело), дата‑время (пресеты: сегодня / завтра / +2ч), заголовок.
3. Создание `crm.activity` / todo на текущего пользователя + `OWNER` = сделка.
4. Возврат ссылки на созданное дело в чат (опционально одной строкой).

## 7) Что кодируем
- Placement чата CRM / IM‑контекст сделки
- `crm.activity.todo.add` (или `crm.activity.add`) с `responsibleId` = текущий пользователь
- Определение `ownerTypeId`/`ownerId` из контекста чата сделки

## 8) Чем НЕ штатив / робот
- Штатив: дело создаётся из карточки/таймлайна, не из чата сделки одним жестом.
- Робот/БП: не «при сообщении создай дело», а явный клик человека в момент договорённости.
- Не «создать сделку из сообщения» (другой job).

## 9) Риски
- На части порталов чат сделки слабо отличим от общего IM — нужна проверка привязки к CRM.
- Не читать текст сообщений в MVP (заголовок вводит пользователь или короткий пресет).
